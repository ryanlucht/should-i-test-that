The user must create an IAM OIDC identity provider and a deployment role in AWS. Provide these exact step-by-step instructions:

**Step 1: Create GitHub OIDC Identity Provider in AWS**

1. Go to AWS Console -> IAM -> Identity providers -> "Add provider"
2. Provider type: **OpenID Connect**
3. Provider URL: `https://token.actions.githubusercontent.com`
4. Click "Get thumbprint"
5. Audience: `sts.amazonaws.com`
6. Click "Add provider"

**Step 2: Create IAM Deployment Role**

1. Go to IAM -> Roles -> "Create role"
2. Trusted entity type: **Web identity**
3. Identity provider: `token.actions.githubusercontent.com`
4. Audience: `sts.amazonaws.com`
5. Click Next
6. Attach these AWS managed policies:
   - `AmazonS3FullAccess`
   - `CloudFrontFullAccess`
   - `AmazonRoute53FullAccess`
   - `AWSCertificateManagerFullAccess`

   Then also create and attach a custom inline policy named `CDKDeployPolicy`:
   ```json
   {
     "Version": "2012-10-17",
     "Statement": [
       {
         "Sid": "CDKBootstrapAndDeploy",
         "Effect": "Allow",
         "Action": [
           "cloudformation:*",
           "ssm:GetParameter",
           "sts:AssumeRole",
           "iam:PassRole",
           "iam:CreateRole",
           "iam:AttachRolePolicy",
           "iam:PutRolePolicy",
           "iam:DeleteRole",
           "iam:DeleteRolePolicy",
           "iam:DetachRolePolicy",
           "iam:GetRole",
           "iam:GetRolePolicy",
           "iam:TagRole",
           "lambda:*",
           "ecr:*"
         ],
         "Resource": "*"
       }
     ]
   }
   ```
   (CDK needs these for CloudFormation deployment, custom resources, and the BucketDeployment Lambda that syncs assets.)

7. Role name: `GitHubActionsDeployRole`
8. Click "Create role"

**Step 3: Restrict Trust Policy to This Repo**

1. Go to IAM -> Roles -> GitHubActionsDeployRole -> Trust relationships -> "Edit trust policy"
2. Replace the Condition block with:
   ```json
   "Condition": {
     "StringEquals": {
       "token.actions.githubusercontent.com:aud": "sts.amazonaws.com"
     },
     "StringLike": {
       "token.actions.githubusercontent.com:sub": "repo:YOUR_GITHUB_ORG/should-i-test-that:*"
     }
   }
   ```
   Replace `YOUR_GITHUB_ORG` with your actual GitHub username or org name.
3. Click "Update policy"

**Step 4: Bootstrap CDK (one-time)**

Run this in your terminal (not in GitHub Actions):
```bash
cd infra
npx cdk bootstrap aws://YOUR_ACCOUNT_ID/us-east-1
```
Replace `YOUR_ACCOUNT_ID` with your 12-digit AWS account ID. This creates the CDKToolkit stack that CDK needs for asset staging.

**Step 5: Copy the Role ARN**

From IAM -> Roles -> GitHubActionsDeployRole, copy the Role ARN. It looks like:
`arn:aws:iam::123456789012:role/GitHubActionsDeployRole`

The user must point GoDaddy's nameservers to Route 53. Per D-05, provide step-by-step instructions:

**Step 1: Open GoDaddy DNS Management**

1. Go to https://dcc.godaddy.com/manage-dns (or My Products -> shouldwetestthat.com -> DNS)
2. Scroll down to **Nameservers** section
3. Click "Change" (or "I'll use my own nameservers")

**Step 2: Replace Nameservers**

1. Delete all existing GoDaddy nameservers
2. Add the 4 Route 53 nameservers from the deploy output:
   - `ns-XXXX.awsdns-XX.org`
   - `ns-XXX.awsdns-XX.co.uk`
   - `ns-XXX.awsdns-XX.net`
   - `ns-XX.awsdns-XX.com`
3. Click "Save"

**Step 3: Wait for DNS Propagation**

- DNS propagation takes 15-60 minutes (sometimes up to 48 hours, but usually fast)
- ACM certificate validation will happen automatically once Route 53 is authoritative
- You can check propagation at: https://dnschecker.org/#NS/shouldwetestthat.com

**Step 4: Verify Certificate Status**

1. Go to AWS Console -> Certificate Manager (make sure you are in us-east-1)
2. Find the shouldwetestthat.com certificate
3. Status should change from "Pending validation" to "Issued" after DNS propagates
4. This may take 5-30 minutes after nameserver change

**Step 5: Test the Custom Domain**

Once the certificate is "Issued", visit:
- https://shouldwetestthat.com
- https://www.shouldwetestthat.com
- http://shouldwetestthat.com (should redirect to HTTPS)

All three should load the app.

**Troubleshooting:**
- If certificate stays "Pending" for >1 hour: Check that Route 53 hosted zone has CNAME records for `_acm-validation.shouldwetestthat.com` (CDK creates these automatically via DNS validation)
- If site shows "403 Forbidden": CloudFront may need a cache invalidation -- go to CloudFront -> distribution -> Invalidations -> Create invalidation -> `/*`
- If site shows CloudFront error: DNS may not have propagated yet. Wait and retry.

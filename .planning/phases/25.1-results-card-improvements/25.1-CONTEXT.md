# Phase 25.1: Results Card Improvements - Context

**Gathered:** 2026-04-08
**Status:** Ready for planning

<domain>
## Phase Boundary

Redesign the results section so non-statisticians can understand why the calculator produced its value. Add a plain-English "why this result" waterfall, split the directional decision impact, rename cards for clarity, and add collapsed FAQ accordion explainers. Keep the default screen clean and uncluttered.

</domain>

<decisions>
## Implementation Decisions

### Accordion Explainers
- **D-01:** Start with the 4 accordion questions defined in SPEC.md (value drivers, how value is calculated, what changes value, why waiting costs). Opus may recommend additional questions during research.
- **D-02:** All accordions collapsed by default — deeper explanation available on demand, not cluttering the core UI.
- **D-03:** Answer content will be AI-drafted by an Opus model during the research/planning phase, following the spec's suggested template structure with dynamic variable interpolation (e.g., `{{netValue}}`, `{{priorLow}}`). Drafts are a research deliverable for PM review before coding begins.
- **D-04:** Skip personalized driver ranking in Accordion 3 ("the biggest drivers appear to be X and Y"). Use the generic "worth more / worth less" lists without new sensitivity calculation logic.

### Waterfall, Decision Impact, Card Renaming
- **D-05:** Follow SPEC.md as-is for these areas — spec is clear enough for planning without additional discussion:
  - Plain-English "Why this result?" waterfall visible by default with 6 numbered steps
  - "Threshold" renamed to "Shipping rule"
  - Single "P(Decision Change)" split into directional "Stops you from shipping" / "Convinces you to ship"
  - Statistical interpretation box kept but streamlined per spec

### Claude's Discretion
- Exact prose tone and sentence structure for the waterfall steps
- Visual treatment of the waterfall (compact enough to not overwhelm the page)
- Whether to recommend additional accordion questions beyond the spec's 4 during research
- Accordion component implementation approach (reuse existing ChevronDown/ChevronUp pattern from ValueBreakdownCard)

</decisions>

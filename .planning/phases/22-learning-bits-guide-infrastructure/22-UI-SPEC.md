The checker rule limits a spec to 2 declared weights maximum. This spec declares 4 Inter weights (400, 500, 600, 700), which exceeds that limit.

**This is a project-level exception, not a spec deficiency.** The Inter 400/500/600/700 weights are pre-existing tokens established in `src/index.css` and cited in `CLAUDE.md` ("Key design tokens") as the project's canonical type scale. Phase 22 does not introduce any of these weights — it inherits them from the running app.

Phase 22 introduces exactly 2 NEW weights for the new typeface: Space Grotesk 400 and Space Grotesk 700. Inter weights are inherited from the existing codebase baseline and are not subject to this phase's weight budget.

## Interaction Contract

### Dialogue Overlay (GUIDE-01)

**Layout:** `fixed bottom-8 right-8 z-50` — sits above calculator content (z-50 > progress indicator z-40).

**Expanded state:**
- Card: `max-w-md` (448px), `bg-white`, `p-5`, `rounded-lg`, `rpg-dialog-box` class (3px solid #7C3AED border + 6px offset shadow)
- Avatar: left side, `w-16 h-16 rounded-full border-2 border-primary bg-primary overflow-hidden` — displays `Learning Bits.png`
- Character name: "Learning Bits" in `font-bold text-primary text-sm` (Space Grotesk 700, 14px)
- Dialogue text: `text-sm leading-relaxed text-foreground` (Space Grotesk 400, 14px, line-height 1.6)
- Bouncing dots: appear after typewriter completes — `inline-flex` with three `animate-dot-bounce` spans
- Close button: `absolute top-2 right-2` — Lucide `X` icon (16px), `text-primary hover:text-[#6D28D9]`

**Collapsed state (post-dismiss, D-07):**
- Collapses to `LearningBitsBubble`: same `fixed bottom-8 right-8 z-50` position
- Button: `w-16 h-16 rounded-full bg-primary border-2 border-primary` displaying `Learning Bits.png` (same avatar image)
- Click reopens `LearningBitsOverlay` and sets `guideEnabled: true` in store

### Typewriter Hook (GUIDE-01)

- Speed: 30ms per character (recommended default — executor discretion per CONTEXT.md)
- Transition between messages: instant text swap then restart typewriter (no fade — executor discretion)
- `prefers-reduced-motion`: Skip animation, render full text immediately
- Screen reader: `sr-only` span with full message text; aria-live region on dialogue container

### Section-Aware Triggers (GUIDE-02)

| Message | Trigger | Stays Until |
|---------|---------|-------------|
| 1 | Initial page load | Baseline Metrics section completed |
| 2 | First focus on Uncertainty (Prior) section | Next message triggered |
| 3 | Click "I want to define the shape..." accordion link; re-triggers on shape option click | Next message triggered |
| 4 | Focus inside lower/upper bound inputs in Uncertainty section | Next message triggered |
| 5 | Shipping Threshold section comes into view (scroll-spy) | User advances to Experiment Design |
| 6 | Experiment Design section focus or any input focus inside | Next message triggered |
| 7 | Click "I want to consider time lag..." accordion; focus inside advanced timing inputs | — |

Source: `22-CONTEXT.md` D-12; `dialogue_draft1.txt`.

### Accordion Components (D-08, D-10)

**Prior shape accordion:**
- Toggle link: `text-sm font-medium text-primary underline cursor-pointer` (Inter 500, 14px, purple)
- Copy: "I want to define the shape of the prior distribution (advanced)"
- Default state: closed (PriorShapeForm hidden)
- Expanded: PriorShapeForm renders inline below toggle

**Advanced timing accordion:**
- Toggle link: same styling as prior shape accordion
- Copy: "I want to consider time lag of metrics or decision-making"
- Default state: closed (advanced timing fields hidden)
- Expanded: timing fields render inline below toggle

### Highlight Pulse (D-09)

- Trigger: `Math.abs(impliedExpectedLift) > 0.01` (lift outside -1% to +1%)
- Effect: rectangular `border-2 border-primary rounded-sm` outline around "Implied expected lift: X%" display; keyframe `highlight-pulse` plays once (scale 1.0 → 1.02 → 1.0, duration 0.6s, `animation-fill-mode: forwards`)
- Remove: when lift returns to within ±1% range

### Toggle Persistence (GUIDE-03)

- `guideEnabled: boolean` added to `wizardStore`
- Persisted via `partialize()` to `sessionStorage` (within-session persistence)
- New sessions (fresh tab): default `true` (guidance ON)
- Close button (X): sets `guideEnabled: false`, collapses to bubble
- Bubble click: sets `guideEnabled: true`, expands overlay

## Dialogue Content (Final — D-11)

| # | Trigger | Text |
|---|---------|------|
| 1 | Page load | "If we want to calculate the value of running a test, first we'll need to define the _stakes_ of the decision in question. Let's start with context - what metric could our changes affect, how many users would be exposed to the change annually, and how do we convert that metric into dollars?" |
| 2 | Uncertainty section focus | "Now we need to describe our uncertainty about the change's true effect. For this calculator, think of a range that you believe has about a 90% chance of containing the real underlying lift from our change. (acknowledging this is a _prior_, a pre-experiment guess)" |
| 3 | Prior shape accordion open / shape click | "Some companies have found compelling evidence that true effects across experiment outcomes follow \"fat-tailed\" distributions - so you can select one here to put more weight on rare large effects. Both of these other alternate distribution shapes might change the estimated value of testing, especially when larger wins or losses matter to your shipping rule." |
| 4 | Lower/upper bound input focus | "As a rule of thumb, keeping your prior centered around 0% is usually a good starting point (unless you feel very strongly otherwise). Most meta-analysis of product A/B tests show relatively small effects centered around 0." |
| 5 | Shipping Threshold section in view | "Most of the time, teams will ship any change that shows likely positive impact, but that's not always the case! To calculate the value of running an experiment, we need to know what you would do in the absence of more data, and what result would be strong enough to change that decision?" |
| 6 | Experiment Design section / input focus | "Finally, we need to consider how _informative_ we expect this experiment to be. Sample information is not perfect – so longer tests with more usable traffic, which usually means more precise results, makes the information from the test more valuable." |
| 7 | Advanced Timing accordion / input focus | "Some metrics take time to mature, and teams often need extra time to analyze results and decide what to do. Both kinds of delay reduce the value of testing, because you have to wait longer to act on what you learn." |

Source: `dialogue_draft1.txt` (final copy — D-11 confirmed, PM content blocker resolved).

Italicized words in dialogue (_stakes_, _prior_, _informative_) render as `<em>` or `font-italic`.

## Accessibility Contract

- `prefers-reduced-motion: reduce`: `useTypewriter` skips character animation, renders full text immediately
- Screen readers: `aria-live="polite"` on dialogue text container; `sr-only` with full current message text always present
- Close button: `aria-label="Close Learning Bits guidance"`; minimum 44px tap target via padding
- Collapsed bubble: `aria-label="Open Learning Bits guidance"`; `role="button"`
- Accordion toggles: `aria-expanded` attribute toggled; `aria-controls` pointing to accordion content id
- Highlight pulse: `aria-live` not needed (visual only); no announcement on trigger

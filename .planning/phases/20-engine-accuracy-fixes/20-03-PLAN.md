<objective>
Make feasibility truncation handling consistent across EVSI, net value, default decision, and fast-path routing.

Purpose: The current code computes an effective truncated prior mean but throws it away for the default decision. The truncation heuristic only checks the lower bound (-1) and misses upper-bound truncation (which matters when CR0 is large). The Normal fast path bypasses truncation entirely. Rejection sampling has a hard 10x cap that silently degrades results. Per the supplementary remediation doc, prior attempts to fix this were partial — this plan covers ALL code paths.

Output: Consistent feasibility handling in evsi.ts, net-value.ts, and useEVSICalculations.ts. Truncation detected by actual tail mass. Default decision uses truncated mean. Fast path gated by tail mass. Rejection sampling made adaptive.
</objective>

       ```typescript
       /**
        * Compute fraction of prior mass outside feasible lift bounds [L_min, L_max].
        * Used to detect when truncation is material and the Normal fast path should be bypassed.
        *
        * @param prior - Prior distribution
        * @param CR0 - Baseline conversion rate (determines L_max = 1/CR0 - 1)
        * @returns Fraction of prior mass outside [L_min, L_max], range [0, 1]
        */
       export function computeInfeasibleTailMass(
         prior: PriorDistribution,
         CR0: number
       ): number {
         const { L_min, L_max } = liftFeasibilityBounds(CR0);
         // Mass below L_min (-1) + mass above L_max (1/CR0 - 1)
         const massBelow = cdf(L_min, prior);          // P(L < -1)
         const massAbove = 1 - cdf(L_max, prior);      // P(L > 1/CR0 - 1)
         return massBelow + massAbove;
       }
       ```

- **TRUNCATION_DISPLAY_THRESHOLD**: Named constant `0.001` (0.1 percentage points) exported from AdvancedResultsSection.tsx. Uses strictly-greater-than comparison to prevent false positives from floating-point noise.
- **NaN guard**: `effectivePriorMean` from engine results guarded with `!isNaN()` check, falling back to `rawPriorMean`. Applied in both AdvancedResultsSection.tsx and ExportCard.tsx (addresses Codex review HIGH concern about NaN propagation).
- **Truncation disclosure**: When `|effectivePriorMean - rawPriorMean| > 0.001`, shows "After feasibility truncation: +X.X%" in the Prior Belief card and "(effective: +X.X%)" in the export card.
- **Timing costs sign**: Changed from `timingCostsDollars > 0 ? '-' : ''` (suppressing negative) to `timingCostsDollars > 0 ? '-' : timingCostsDollars < 0 ? '+' : ''` (honest display). Applied in both ValueBreakdownCard.tsx and ExportCard.tsx.
- **Estimate label**: Timing costs label changed from "Timing costs" to "Timing costs (est.)" with tooltip explaining the derivation.
- **Assumption note**: Added "Value scaled to all annual visitors (assumes full rollout after test)" to both results section and export card (D-04).
- **Stale comment fix**: Removed ADV-OUT-02 ("Y = max(0, EVSI - CoD)") and ADV-OUT-04 ("Cost of Delay display") from header comment (Other-3).

### Task 2: Store Cleanup and URL Validation (TDD)

- **sharedNetValue removed**: Deleted from WizardState interface, WizardActions, wizardStore initial state, setInput clearing logic, setSharedNetValue action, and resetWizard. No references remain anywhere in src/.
- **SCHEMA_VERSION bumped to 2**: Identity migration `1: (payload) => ({ ...payload, v: 2 })` added. Existing v0 and v1 payloads migrate through the chain correctly.
- **Version-aware validation**: `validateDecodedPayload` now receives `originalVersion` (captured before migration). For v2+: baselineConversionRate must be in `(0, 1)` (open interval), trafficSplit must be in `[0.10, 0.90]`. For v1: original loose rules preserved (`[0, 1]` for CR, `(0, 1]` for split).
- **TRUNCATION_DISPLAY_THRESHOLD boundary tests**: Added 2 tests confirming delta of exactly 0.001 does NOT trigger disclosure (strictly greater than) while 0.0011 does.
- **URL codec tests**: 6 new v2 validation tests (reject CR=0, CR=1, split<10%, split>90%; accept split=10%, CR=0.001) and 2 backward compatibility tests (v1 with CR=0, v1 with split=95%).

## Decisions Made

1. **Strictly-greater-than for truncation threshold**: `Math.abs(delta) > TRUNCATION_DISPLAY_THRESHOLD` rather than `>=`. This prevents spurious truncation disclosure when floating-point noise produces a delta of exactly 0.001, which is not meaningful truncation.

2. **originalVersion preserved pre-migration**: The version from the decoded payload is captured before the migration chain runs. This ensures v1 payloads (which may have been created with loose validation) continue to decode with their original loose rules, even though they get migrated to v2 data format.

3. **SupportingCard conditional rendering**: When truncation is material, the Prior Belief card uses the `children` prop to render both the value and truncation annotation. When not material, uses the standard `value` prop. This avoids the issue where `children` would replace the value display.

4. **ExportCard decimal comparison**: `effectivePriorMean` is in lift-unit form (decimal, e.g., 0.05) while `prior.meanPercent` is in percentage form (e.g., 5.0). The comparison correctly converts rawPriorMean from percentage to decimal (`/ 100`) before computing the delta.

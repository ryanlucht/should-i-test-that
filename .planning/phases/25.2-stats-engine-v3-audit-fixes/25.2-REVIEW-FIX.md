## Fixed Issues

### CR-01: Unit mismatch in truncation comparison (AdvancedResultsSection)

**Files modified:** `src/components/results/AdvancedResultsSection.tsx`
**Commit:** 7aaf59e
**Applied fix:** Added `rawPriorMeanDecimal = rawPriorMean / 100` conversion so the truncation comparison (`truncationMaterial`) compares `effectivePriorMean` (decimal lift) against `rawPriorMeanDecimal` (decimal lift) instead of the percentage-form `rawPriorMean`. Also updated the NaN fallback to use `rawPriorMeanDecimal`. Existing tests (symmetric interval where mean=0) continue to pass; an asymmetric prior would now correctly avoid false truncation disclosure.

### WR-01: Missing `mode` discriminant prop on ExportButton

**Files modified:** `src/components/results/AdvancedResultsSection.tsx`
**Commit:** 9f10b8c
**Applied fix:** Added `mode="advanced"` prop to the ExportButton call in AdvancedResultsSection. Without this, the discriminated union defaulted to undefined, causing the component to fall through to basic mode code paths.

### WR-02: Stale worker reference captured in cleanup closure

**Files modified:** `src/hooks/useEVSICalculations.ts`
**Commit:** 01b0144
**Applied fix:** Replaced the captured `const currentWorker = workerRef.current` snapshot (which was always null/stale before the async Worker creation) with a direct read of `workerRef.current` inside the cleanup function. The ref object identity is stable across renders, so this safely terminates workers created by the async `runWorker()` call.

### WR-03: Redundant `computeEffectivePriorMetrics` call in `finalResults` memo

**Files modified:** `src/hooks/useEVSICalculations.ts`
**Commit:** bcd164a
**Applied fix:** Added `effectiveMetricsRef` to cache the result of `computeEffectivePriorMetrics` from the useEffect. The finalResults useMemo now reads from the cached ref instead of recomputing. A safe fallback to recompute is retained if the ref is unexpectedly null.

### WR-04: Missing keyboard event handling on expandable timing costs row

**Files modified:** `src/components/results/ValueBreakdownCard.tsx`
**Commit:** 4cb816c
**Applied fix:** Replaced `div[role="button"]` with a native `<button type="button">` element. This eliminates the need for manual `role`, `tabIndex`, and `onKeyDown` handlers, providing native keyboard interaction and screen reader support. Added reset styles (`bg-transparent border-none p-0 text-left font-inherit w-full`) to preserve the existing visual appearance.

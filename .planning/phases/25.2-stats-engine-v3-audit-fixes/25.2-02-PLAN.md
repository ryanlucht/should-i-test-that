    **Step A: Fix the inline parameter computation in UncertaintyPriorForm.tsx.**

    Currently (around line 192-195), the form uses `computePriorFromInterval` for ALL prior shapes, which uses the Normal z_0.95 calibration. This is wrong for Student-t.

    Replace the `priorParams` computation with logic that dispatches based on `inputs.priorShape`:

    ```typescript
    // Import buildPriorFromInputs if not already imported
    import { computePriorFromInterval, buildPriorFromInputs } from '@/lib/prior';

    // Compute prior parameters with correct calibration per shape
    const priorParams = useMemo(() => {
      if (intervalLow === undefined || intervalHigh === undefined) return null;

      if (inputs.priorShape === 'student-t') {
        // Student-t: use t-quantile calibration via buildPriorFromInputs
        // This ensures the displayed scale matches what the engine actually uses
        const prior = buildPriorFromInputs({
          priorShape: 'student-t',
          studentTDf: inputs.studentTDf ?? 5,
          intervalLowPercent: intervalLow,
          intervalHighPercent: intervalHigh,
        });
        return { mu_L: prior.mu_L!, sigma_L: prior.sigma_L! };
      }

      // Normal: use standard z_0.95 calibration
      return computePriorFromInterval(intervalLow, intervalHigh);
    }, [intervalLow, intervalHigh, inputs.priorShape, inputs.studentTDf]);
    ```

    Note: Wrap in `useMemo` with appropriate deps to avoid recomputing on every render. Add `useMemo` to the React import if not already present.

    **Step B: Rename the Student-t label from 'sigma' to 'scale' with explanatory tooltip.**

    Addresses review concern: renaming sigma to "scale" could reduce clarity for stats-aware users.

    it('Student-t scale differs from Normal sigma for same interval', () => {
      const normalParams = computePriorFromInterval(-8.22, 8.22);
      const prior = buildPriorFromInputs({

        studentTDf: 5,

The `EVSIVerdictCard` always prefers `sharedNetValue` over `netValueDollars` when `sharedBaseline !== null` (line 56).     **Fix:** Use `useSharedDiff` to detect when inputs diverge from the shared baseline. When ANY field is modified, exit recipient mode by treating the live computed value as authoritative.

    **Design decision (addresses Codex MEDIUM concern about revert behavior): Divergence is ONE-WAY for the session.** Once the recipient edits ANY field, recipient mode is permanently exited for that session. Even if the user manually reverts all edits back to the sender's exact values, the app continues showing live computed values. Rationale:
    - Simpler mental model: "I edited, so I own these results now"
    - Avoids subtle UX bugs where toggling between modes confuses users
    - The live computed value and the sender's value should converge anyway if inputs match
    - Two-way toggle would require deep-equality comparison on every render (performance concern)

    **Root cause:** The dirty callbacks in CalculatorPage (`handleBaselineDirty` etc.) have `completedSections` in their dependency array. When the user clicks Continue and `markSectionComplete` updates `completedSections`, the callback identity changes. This causes React to re-run the `useEffect([isDirty, onSectionDirty])` in each form. Since RHF does not reset `isDirty` after submit, the effect fires `onSectionDirty()` on the section that was just completed, immediately invalidating it.

    **Fix strategy:** Use a ref-based approach in each form to track the dirty transition, so invalidation fires only on the FALSE-to-TRUE transition of `isDirty`, not on callback identity changes.

    **Step 1: Fix each form's dirty-detection effect.**

    In **BaselineMetricsForm.tsx**, replace the current effect (around lines 80-90):
    ```typescript
    // OLD:
    // const { formState: { isDirty } } = methods;
    // useEffect(() => {
    //   if (isDirty && onSectionDirty) {
    //     onSectionDirty();
    //   }
    // }, [isDirty, onSectionDirty]);
    ```

    With a ref-based clean-to-dirty transition detector:
    ```typescript
    // CR28-03: Fire invalidation only on the false-to-true transition of isDirty.
    // A stable ref tracks previous dirty state so that callback identity changes
    // (from completedSections updates) do not re-fire the invalidation.
    const { formState: { isDirty } } = methods;
    const wasDirtyRef = useRef(isDirty);

    useEffect(() => {
      // Only fire on the clean-to-dirty transition (false -> true)
      if (isDirty && !wasDirtyRef.current && onSectionDirty) {
        onSectionDirty();
      }
      wasDirtyRef.current = isDirty;
    }, [isDirty, onSectionDirty]);
    ```

    Add `useRef` to the import from 'react' if not already imported.

    Apply the SAME pattern to:
    - **UncertaintyPriorForm.tsx** (around lines 165-175)
    - **ThresholdScenarioForm.tsx** (around lines 250-260)
    - **ExperimentDesignForm.tsx** (around lines 90-105)

    In each form, the pattern is identical:
    1. Add `const wasDirtyRef = useRef(isDirty);` before the useEffect
    2. Change the condition from `if (isDirty && onSectionDirty)` to `if (isDirty && !wasDirtyRef.current && onSectionDirty)`
    3. Add `wasDirtyRef.current = isDirty;` inside the effect body

    **Step 2: Remove completedSections from callback dependencies in CalculatorPage.tsx.**

    Since the ref-based approach in forms now protects against spurious re-fires, we can make the dirty callbacks stable by removing the `completedSections` gate. This is OPTIONAL but cleaner -- the forms already only fire on the first dirty transition. However, the gate is still a useful optimization to avoid even calling invalidateSection when the section isn't completed. Keep the gate but make it stable via `useRef`:

    In CalculatorPage.tsx, replace the current pattern:
    ```typescript
    const handleBaselineDirty = useCallback(() => {
      if (completedSections.includes(0)) {
    ```

    Place the `completedSectionsRef` declaration once, above all four callbacks.

  <name>URL Codec: encode/decode WizardInputs with schema versioning</name>
  <files>src/lib/url-codec.ts, src/lib/url-codec.test.ts</files>

  </read_first>
  <behavior>
    - Round-trip: encodeWizardState(inputs) |> decodeWizardState === inputs (for all non-null fields)
    - Compactness: A typical scenario (baselineConversionRate=0.05, annualVisitors=500000, valuePerConversion=50, priorType='custom', priorIntervalLow=-5, priorIntervalHigh=10, priorShape='normal', thresholdScenario='any-positive', testDurationDays=14, dailyTraffic=2000, trafficSplit=0.5, eligibilityFraction=1.0, decisionLatencyDays=0) encodes to under 400 characters total (including the "#s=" prefix)
    - Null omission: Fields that are null are NOT included in the encoded JSON; fields matching initialInputs defaults (trafficSplit=0.5, eligibilityFraction=1.0, decisionLatencyDays=0, priorShape='normal', visitorUnitLabel='visitors') are also omitted
    - Schema version: Encoded payload includes "v":1 integer; decodeWizardState reads this version
    - Migration chain: When version in payload < SCHEMA_VERSION, a migration function is called per version step (v1->v2, v2->v3, etc.)
    - Decode of unknown version: Returns null (not throw) so caller can handle gracefully
    - Decode of malformed string: Returns null (not throw)
    - Decode fills missing keys with initialInputs defaults (forward compat: new fields added later get defaults)
    - Short keys: Each WizardInputs key maps to a 1-2 character short key (e.g., baselineConversionRate -> "bc", annualVisitors -> "av", etc.)
    - Encoding uses hash fragment format: the encoded string is meant to be placed after "#s=" in the URL
  </behavior>
  <implementation>
    Create src/lib/url-codec.ts with:

    1. SHORT_KEY_MAP: Record mapping full WizardInputs keys to short 1-2 char keys:
       - baselineConversionRate -> "bc"
       - annualVisitors -> "av"
       - visitorUnitLabel -> "ul"
       - valuePerConversion -> "vc"
       - priorType -> "pt"
       - priorIntervalLow -> "pl"
       - priorIntervalHigh -> "ph"
       - priorShape -> "ps"
       - studentTDf -> "df"
       - thresholdScenario -> "ts"
       - thresholdUnit -> "tu"
       - thresholdValue -> "tv"
       - testDurationDays -> "td"
       - dailyTraffic -> "dt"
       - trafficSplit -> "sp"
       - eligibilityFraction -> "ef"
       - decisionLatencyDays -> "dl"

    2. REVERSE_KEY_MAP: Computed inverse of SHORT_KEY_MAP

    3. SCHEMA_VERSION = 1

    4. DEFAULT_OMIT_VALUES: Values that match initialInputs defaults and should be omitted from encoding to save space. Use initialInputs directly for comparison.

    5. encodeWizardState(inputs: WizardInputs): string
       - Build compact object: for each key in WizardInputs, if value !== null AND value !== initialInputs[key], add SHORT_KEY_MAP[key]: value
       - Add "v": SCHEMA_VERSION
       - JSON.stringify the compact object
       - Base64url encode (btoa with URL-safe chars: + -> -, / -> _, remove trailing =)
       - Return the encoded string (caller adds "#s=" prefix)

    6. decodeWizardState(encoded: string): WizardInputs | null
       - Try: base64url decode (reverse the URL-safe char substitution, atob)
       - Try: JSON.parse
       - Read "v" field; if missing or > SCHEMA_VERSION, return null
       - If v < SCHEMA_VERSION, run migration chain (future-proofing scaffold)
       - Map short keys back to full keys using REVERSE_KEY_MAP
       - Merge with initialInputs (spread initialInputs first, then decoded values on top) so missing keys get defaults
       - Return the merged WizardInputs

    7. Type the function signatures with JSDoc comments explaining the encoding format.
  </implementation>

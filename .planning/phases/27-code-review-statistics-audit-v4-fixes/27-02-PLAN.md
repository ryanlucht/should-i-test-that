<objective>
Fix the HIGH severity stale-values bug (CR-1): after completing all wizard sections, editing an input field without re-submitting the section leaves results, share links, and PNG exports reflecting the old store values.

The root cause is that `completedSections` never gets un-completed when a user edits inputs in an already-completed section. The fix adds an `invalidateSection` action that removes a section (and all downstream sections) from `completedSections` whenever an input value changes in a completed section.

Purpose: Prevent incorrect results from being displayed, shared, or exported when inputs have been changed.
Output: Store with invalidation logic, CalculatorPage wiring, and integration test.
</objective>

    **Step 4: Modify `setInput` to auto-invalidate (src/stores/wizardStore.ts):**

    Update the existing `setInput` to check if the field's section is in completedSections, and if so, call invalidateSection:

    ```typescript
    setInput: <K extends keyof WizardInputs>(key: K, value: WizardInputs[K]) => {
      set((state) => {
        const section = SECTION_FIELD_MAP[key];
        const needsInvalidation = section !== undefined && state.completedSections.includes(section);
        return {
          inputs: { ...state.inputs, [key]: value },
          // Remove this section and all downstream sections when editing a completed section
          ...(needsInvalidation
            ? { completedSections: state.completedSections.filter((s) => s < section) }
            : {}),
        };
      });
    },
    ```

    This is a single atomic `set` call that updates both inputs and completedSections, avoiding intermediate inconsistent state.
